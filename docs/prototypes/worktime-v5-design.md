# 我的工时与组织统计权限 · V5

2026-09-22。当前设计以 V5 为准；V1 至 V4 仅作历史对照。本次交付是高保真可点击 HTML 原型，不是正式业务实现。

## 1. 本次调整

| 入口或能力 | 普通成员 | 组织管理员 |
| --- | --- | --- |
| 侧栏「工时统计」 | 隐藏，不可进入 | 当前组织全部企业项目的统计 |
| 侧栏「我的工时」 | 本人记录与本人统计 | 仍然只有本人记录与本人统计 |
| 我的工时 → 工时统计 | 按项目汇总本人的已确认、未确认与总投入；本人周/月趋势 | 相同口径，不因管理身份扩大范围 |
| 项目篮子的「项目工时」入口 | 隐藏 | 显示 |
| 项目详情 | 项目待办、项目日记、交付工作台三个 Tab | 上述三个 Tab，加第四个「项目工时」 |
| 新建企业项目 / 企业待办 | 不可创建 | 可以创建，企业待办预估必填 |
| 任务验收 | 仅该任务真实创建人有验收权 | 同样只限创建人，不允许其他管理员代验收 |

成员的企业工时导航只剩「我的工时」。待我验收属于任务处理，放入「日常工作」，有创建任务记录的账号可以进入；不构成组织统计权限。普通成员样例没有创建任务，所以不会显示此入口。

本轮同时移除了成员项目任务列表的全体实际工时列。任务预估、状态、负责人和创建人仍保留，便于协作。普通成员打开任务详情时，实际投入与流水只显示本人数据，标签写为「我的已确认 / 我的未确认」。创建人验收所需的任务级完整提交明细是明确的业务权限，不授予跨项目、跨成员报表权限。

## 2. 我的工时

页面采用「工时记录 / 工时统计」两个 Tab。顶部保留记录工时与导出操作，并明确当前姓名与「仅本人记录 · 不含个人项目」。在两个 Tab 间切换时保留项目、周/月周期；确认状态筛选仅作用于工时记录。

- 工时记录：按工作日期倒序，显示项目、任务、说明、本次小时数与确认状态。只有本人仍可填报任务的未确认记录能修改；已提交验收或已确认记录锁定。
- 工时统计：已记录、已确认、未确认、参与项目四项指标；本人的投入趋势、项目分布与项目投入明细。没有成员选择器，也不显示全项目预估或全体成员偏差。
- 点击项目分布或项目明细行，进入「我的工时 → 工时记录」，自动筛选该项目。不会跳转到管理员项目工时报表。
- 导出范围与当前页面一致：当前用户、授权企业项目、所选项目和周期；记录 Tab 额外应用确认状态。管理员从这里导出也只有自己的数据。
- 无记录时显示空态，汇总为 0，参与项目为 0。历史已完成但未记录的任务不会生成虚假的零小时流水。

统计先按工时作者筛选，再按项目与日期筛选。任务改派不会改变历史作者，不能把整项任务的总工时归给当前负责人。

## 3. 记录工时：项目 → 任务

1. 从我的工时打开表单时，项目和任务均不默认选中；任务显示「请先选择项目」并禁用。
2. 项目下拉仅列出当前组织中有权访问的企业项目，个人项目不参与。
3. 选择项目后，任务下拉只包含该项目中本人负责的进行中任务。已提交验收、已完成、无权访问、他人负责的任务不可选。
4. 切换项目时清空原任务，保留已输入的日期、小时数和工作说明，避免错误关联和无谓重填。
5. 项目没有可填报任务时禁用任务与保存按钮，解释原因。修改已有记录时，项目与任务锁定，避免移动历史投入。
6. 从任务详情打开记录工时，自动预填该项目和任务；提交时再次校验关联关系与权限。
7. 工作日期、工时与说明必填；按 0.25 小时递增，每人每天跨项目已确认与未确认之和不超过 24 小时。

保存只新增未确认流水，任务仍为进行中。完成工作后再提交任务验收，由创建人一次确认成果与工时；没有单独的逐条工时审批。

## 4. 延续的业务范围

个人项目完全不改，不加本轮工时统计、强制预估或新验收规则。测试工作台的页面、入口与业务逻辑保持原样。原型侧栏里的既有模块是上下文展示，不代表重新实现或删除其能力。

企业项目详情继续沿用既定 Tab 顺序，隐藏右上角子项目管理与邀请成员。项目日记按项目保留草稿；交付工作台沿用原有事件、文档和安装包浏览结构。

创建企业待办时预估必填、创建人由系统记录，没有可选验收人。负责人记录投入后提交成果，创建人通过则完成并确认本次未确认流水；退回或撤回则保留记录继续修改。重开任务保留已确认工时，返工新增流水，再验收时只确认新增部分。

## 5. 统计口径

已记录 = 已确认 + 未确认。已退回、已作废流水不计入投入；明细导出保留符合筛选条件的状态以便核对。参与项目 / 任务数量只按有效流水计算。个人投入占比的分母是当前筛选下本人的全部有效投入，不是全项目投入。

周为周一至周日，月为自然月；按工作日期归属，界面采用 Asia/Shanghai。月趋势分段为 1–7、8–14 等连续七日，不冒充自然周。未来日期不绘制数据。后续验收会更新原工作周期的确认状态，月结冻结不在本轮范围内。

固定样例 2026 年 9 月：林知远 66h，已确认 18.5h、未确认 47.5h；零售后台重构 48.5h，供应链数据看板 17.5h。周予安的「我的工时」为 34h；顾南枝为 24h。组织统计为已确认 93.5h、未确认 84h，与个人页面严格区分。

## 6. 视觉方案

沿用 Veges 当前 Daily Workbench：白色侧栏、低对比浅底、细边框、绿色主操作，主体使用现有 Inter 字体栈，数值使用现有等宽字体栈。复用从 `src/index.css` 与 `src/App.css` 提取的颜色、220px 侧栏、6px 控件圆角与紧凑间距。

页面重点是个人数字及其项目归属。Tab 采用现有绿色下划线；项目条形图用已确认绿色、未确认琥珀色分段，与趋势和状态保持一致。桌面表格在 375px 下变成项目卡片，填报顺序、字段标签与状态信息保持完整。

沿用现有 CSS 基础层，仅在 V5 增加个人页面样式；没有更换产品主题。个人 Tab 与项目 Tab 支持方向键、Home / End；原生 dialog 提供焦点约束和 Escape 关闭。

## 7. 正式接入计划与权限边界

本原型用演示身份模拟权限，全部样例存在浏览器内存，因此不提供生产级数据隔离。正式接入时必须由服务端执行以下约束，不能仅隐藏入口：

1. 分开提供个人报表与组织报表能力。个人查询和导出从认证用户派生作者 ID，拒绝通过请求参数切换作者。聚合前应用组织、企业项目、访问权限、作者、日期条件，不向浏览器返回其他人的流水后再过滤。
2. 组织与项目工时报表要求 `organization_admin` 账号角色，同时具备当前组织有效 owner/admin 成员身份，返回明确的统计 capability。职业 persona、项目 Owner、普通项目成员、平台管理员身份均不能隐式取得此统计权限。
3. 任务验收单独检查真实创建人、项目访问权、任务状态和提交版本；不能将统计管理能力当作验收权。创建人失去访问权时不自动转交任意管理员。
4. 企业项目与任务创建、任务选择、记录提交都校验实际企业项目归属与当前权限；任务必须隶属于所选项目，作者由服务端派生。企业待办的预估要求覆盖 UI、导入、AI 转待办等创建路径。
5. 采用统一流水计算汇总，保留历史作者与修订审计。提交、验收、撤回、退回、重开与相关工时更新在同一事务中锁定任务并校验版本；每日上限用作者与工作日的事务锁防止并发超额。敏感说明加密保存，创建接口使用幂等键。
6. 按 `AGENTS.md` 同步客户端契约、提醒与验收入口、数据库约束、确认弹窗清单；个人项目和测试工作台做独立回归，避免企业规则外溢。

建议实施顺序：能力与数据契约 → 企业创建和流水 → 创建人验收事务 → 本人查询与导出 → 两层管理员统计 → 权限与并发回归。此处仅更新设计计划，尚未修改正式代码。
